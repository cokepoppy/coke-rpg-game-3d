# 苍山旧道：2D 到 3D 尺度与摆位

## 统一尺度

原地图由两张 `2240 × 3584` 像素图左右拼接，基础布局对应 `44 × 35.2` 米。为回应开场过于拥挤的问题，当前户外关卡将水平布局坐标扩展 `1.6×`，实际场景约 `70.4 × 56.32` 米；人物和建筑的垂直高度与本体尺寸不扩展。因此：

- 基础比例：`1 px = 44 / 4480 = 0.009821 m`
- 当前关卡比例：`1 px = 0.009821 × 1.6 = 0.015714 m`
- 当前 `100 px ≈ 1.571 m`
- 出生点 `(2700, 2520)` 到药摊 `(3090, 2710)` 是 `434 px ≈ 6.82 m`
- 药摊到客栈中心 `(3970, 2730)` 是 `880 px ≈ 13.83 m`

Three.js 与 Blender 均从拼接图左上角像素坐标取锚点，再换算为世界坐标。地标顺序与相对位置仍按原图；当前系数是为关卡留出更宽松的行走空间，不是从 2D 图测得的真实地理尺度。建筑占地以地图轮廓估算；道路宽度也必须从原图像素宽度乘以 1.6 换算，不能再额外放大。当前主路约 2.45 米，支路约 1.85–2.15 米。

## 视觉差异复盘（2026-09-30）

首轮 3D 预览和原图并排后，差异不只是模型精度：原图是暖色泥地、窄弯路径、连续的路缘石/植被簇；程序场景此前只有手工描出的几条中心线，主路宽到 3.85 米，树木又在道路两侧各清空 225 像素，加上大块房屋避让框，路口因此连成大面积纯色空地。底层地形只有单一草绿色，正交像素地图则被透视镜头进一步拉大近景、改变建筑比例。

本轮先修正这些全局量：保留 1.6 倍关卡尺度；将主路收至 2.45 米、支路收至 1.85–2.15 米；道路周边树木缓冲缩到 125 像素、地被缓冲缩到 85 像素；避让框缩至真实建筑和出生点占地附近；地形与土路改成由真实 3D 网格顶点色驱动的多尺度暖色斑驳；游戏镜头改为正交投影，让远近建筑保持原画式的相对尺寸。地图图片仍只作为布局和配色参考，不铺到地面。

这轮属于比例和基底校正，不代表已经复刻原图。要达到接近原图的构图，下一阶段应把两张原地图标成同一像素坐标系的道路、林缘/岩岸、空地、田地、水域语义区域，再从这些区域生成连续路径边界和成簇的 3D 资产。继续堆单体模型无法弥补区域形状、密度和留白错误。

## 开局净空与苏萝

苏萝旧出生点由世界坐标偏移算出约 `(2583, 2408)`，而石灯锚点是 `(2580, 2390)`，两者只有 `18 px ≈ 0.18 m`，所以石灯会穿过她的腰。新出生点使用 `(2840, 2580)`：

- 距沈临川出生点约 `152 px ≈ 2.39 m`，仍处在交谈距离内。
- 距石灯约 `322 px ≈ 5.06 m`，能完整留出人物和石灯的占地。
- 开局路口以树木、花草排除区保持净空。

## 建模来源

沈临川和苏萝的静态外形来自腾讯混元图生 3D 的 GLB；`tools/package_wuxia_character.py` 再做网格简化、程序化骨架权重和动作。云来客栈和秋枫资产已使用混元网格并单独接入。苍山牌坊当前是独立 Blender 真几何模型，用于替代歪斜的临时门架并作为尺寸基准；其 ImageGen 多视图参考已准备好，尚未提交混元生成。药铺、桥、亭、摊位、石灯、井、围栏、普通树和道具仍由场景构建脚本生成，待按资产清单逐类替换。混元 WorldMirror 资产是场景高斯/点云重建，无法直接替代可碰撞、可编辑的房屋或树木网格。

下一步若改为单体 Hunyuan3D 资产，按 `coke-mario` 已验证流程保留原始 GLB、在 Blender 内整理尺寸/网格、预览重导入，再以单件 GLB 接入场景；每件需要与地图像素占地和碰撞范围一起验收。当前开阔度、地标和人物修正继续使用可重复的项目 Blender 脚本，不把 HunyuanWorld 点云误标成已生成的游戏模型。

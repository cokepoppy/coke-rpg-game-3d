# Three.js 武侠 RPG 场景资产流水线

调研日期：2026-09-24。适用于从 2D 像素地图制作可行走、可交互的 Three.js 3D 场景。

## 结论

采用 **“2D 地图定布局 + ImageGen 定造型 + Hunyuan3D 做重要单体 + Blender 整理 + Three.js 按坐标拼场景”** 的混合流程。

整张地图继续提供布局与美术风格；游戏地面和场景物体由可编辑的 3D 几何组成。整图世界生成可用于快速看气氛、镜头和空间方向；单独的房屋、树、牌坊、灯亭、桥和摊位则生成可复用网格，再按 2D 地图锚点逐个摆放。地面、道路、河流、围栏、碰撞代理和交互范围由 Blender/Three.js 确定性制作。

这能同时保留原图的地标位置和游玩路径，并把当前脚本生成的通用房屋、树木换成更有细节的模型。草地和石块按区域布置即可；先生成少数高辨识度资产，再复用树木和道具变体。

## 整图生成与单体资产的职责

腾讯的 [HY-World 2.0](https://github.com/Tencent-Hunyuan/HY-World-2.0) 确实有从文字或单张图生成可探索世界的流程，但官方代码所示的 World Generation 会经过全景生成、路径规划、生成扩展视角、构建训练数据、3D Gaussian Splatting（3DGS）训练；也可将训练结果融合为整块网格。它适合快速得到一片连贯的可视世界，不过这不等于逐一恢复 2D 地图里的对象，更不会自动输出可以单独换皮、碰撞、开门和做剧情交互的每一栋房屋、每一棵树。整图生成会补出输入里看不到的侧面和背面，且视角、间距、入口和遮挡可能重新安排。

本项目原图是两张拼接的 4480×3584 像素 2.5D 地图，输入视角与全景照片或多视角实景采集不同。因此整图重建适合作为空间、氛围和构图参考；精确布局由地图坐标清单控制，角色活动区继续使用带碰撞体的可编辑网格。当前已有的 `cangshan-opening-3dgs.ply` 可用于氛围、纵深和构图参考。

腾讯 [Hunyuan3D](https://github.com/Tencent-Hunyuan/Hunyuan3D-2) 的图像管线面向单体网格：根据物件参考图生成 mesh，再生成贴图；官方也列出多视图生成与给手工网格生成贴图的用法。房屋或树木单独生成后能作为 GLB 资产在 Blender 检查、缩减、复用。输入只有一张 2D 图时，未画出来的部分是模型推断出来的，所以需要先为关键建筑补清楚的视图参考。

| 方法 | 擅长 | 对本项目的边界 |
| --- | --- | --- |
| 整张图 → HY-World / 3DGS | 很快得到整体氛围、构图和可探索的空间感 | 不是按地图锚点逐物件复刻；3DGS/整块融合网格不等于可编辑的独立道具库 |
| 单个物件 → ImageGen → Hunyuan3D | 做有特色、可重复摆放的房屋、树、牌坊、桥、灯亭 | 要先去掉背景并补侧面/背面设计；导出后需在 Blender 修尺寸、底面、拓扑和材质 |
| Blender 程序化几何 | 精确尺寸、确定落点、容易做地面/道路/围栏/碰撞 | 只靠简单体块搭主要建筑和树，会显得像当前预览一样通用、简陋 |
| **混合（推荐）** | 资产外观质量、原图布局、碰撞和交互都可控 | 需要一次性建立图集、坐标清单和资产目录，后续可重复使用 |

## 分层建模规则

1. **高辨识度单体：用 Hunyuan3D。** 苍山牌坊、云来客栈、百草药铺、桥、亭、练功场附近关键灯亭。它们在镜头中面积大，是地图是否“像原图”的主要判断依据。
2. **自然物和重复物：做少量模型变体后复用。** 先做阔叶树、松树、红叶树各 1–2 个高质量模型，和石灯、岩石、木桶、箱子、药摊各若干变体。Three.js 用实例化/共享几何来铺放，不为每个位置单独调用生成模型。
3. **连续结构：继续用 Blender/Three.js 参数化制作。** 地形、土路、溪流、田埂、木围栏、台阶、隐藏碰撞盒和导航边界需要准确衔接，适合从地图路径坐标生成；可用精细网格和材质提高观感，不再用少数大方块代替显眼建筑。
4. **室内单独成套。** 客栈内室沿用 `inn-room.png` 的房间边界和家具锚点；床、柜、书桌、屏风、茶桌、箱子按高低可见度分级建模。账册、箱子、门口这类剧情物件保留独立对象和交互锚点。

## 可复用制作步骤

### 1. 固定地图坐标和区域标注

- 源图 `world-west.png`、`world-east.png` 左右拼为 4480×3584；保留原图作为只读源。
- 给地图建立对象清单：资产 ID、像素中心、底面占地、朝向、房门方向、重要地标/可交互标记、遮挡和禁行范围。
- 先以主角出生区、南侧牌坊到药摊/客栈路段、练武空地为首轮范围。树林按区域簇记录，不把每一片树叶做成资产。
- 坐标清单是“哪里放”的权威来源；模型生成是“物体长什么样”的来源。禁止让模型重排地图布局。

### 2. 从地图裁对象并制作干净参考

- 从原图裁出建筑/树/道具及其周边阴影，保存不改动的原始裁图。
- 俯视 2.5D 裁图只提供配色与装饰，不足以说明建筑四面。用 ImageGen 把**单个对象**整理为一致风格的正面、侧面、背面或 3/4 视图；房屋需明确屋顶厚度、屋檐、墙体、门窗、地基和比例。树需要清楚的树干、树冠体块和树底。
- 参考图保持一种材质语言：武侠像素场景的手绘纹理、略夸张比例、清楚轮廓；白色/透明背景，无文字、地面、人物或额外道具。
- 不要把地图里已有的侧影直接当成正面视图，也不要一次把整片房屋群裁成一个资产。

### 3. Hunyuan3D 单体生成

- 先拿一个可复用的树和一个主要建筑做端到端样件，再按结果调整提示与视图。
- 生成时记录平台、模型版本、提示词、输入视图、种子（若界面提供）、下载日期和原始 GLB；每次生成不覆盖原件。
- 对房屋优先提供正/侧/背图；对同类树使用统一视图规则，之后再生成少数外形变体。薄围栏、瓦片、细柱若生成结果断裂或浮空，改由 Blender 参数化建模。
- 当前人物资产已证明“混元生成单件 GLB → Blender 整理 → Three.js 加载”的本地路径可用；场景资产也复用同样的保留原件、检查预览、重导 GLB 习惯。

### 4. Blender 整理成游戏资产

- 对齐世界上方向和正面方向，应用旋转/缩放；修平底面，把原点放在对象底面中心或预设铰链点。
- 清理浮片、破洞和内部杂面；合并过碎材质，贴图压缩并确认 GLB 内嵌；按资产用途做网格简化。
- 视觉网格与碰撞代理分开。建筑用少量盒体/简化轮廓碰撞；树保留树干碰撞；门、柜、剧情箱等需交互部件不要焊死进不可拆的整体。
- 同步保存原始模型、Blender 检查工程、运行时 GLB、正侧背预览和尺寸记录。

### 5. 按布局装配与运行时优化

- 使用坐标清单在 Blender 中预览摆位，再导出分区 GLB；Three.js 只加载与当前区域有关的网格和碰撞数据。
- 保留单体资产的可替换边界。静态材质相同的重复树/灯具可共享材质与网格，必要时用 `InstancedMesh`；避免把整张地图 join 成一个无法单独替换和做交互的网格。
- 道路和空地先按原图轮廓留出来，再放树、石头和小道具。装饰密度不能侵占主角行走路线、镜头中的轮廓和门前交互区。
- 远处非交互背景可用低成本的简化几何；主角活动区域必须有真网格、明确碰撞和可校准的遮挡关系。3DGS 可另做视觉参考，不替代这些数据。

### 6. 对照验收

- 固定 3 个检查镜头：出生点看向牌坊、药摊到客栈、客栈内室；同位置并排放原图和 3D 截图。
- 先查地图锚点、门方向、道路宽度和空地边界，再查房屋/树的轮廓与高度，最后查纹理、灯光和装饰密度。
- 逐个走通出生点、苏萝对话、客栈门和室内线索；检查女主角、树干、牌坊、屋檐没有压进地面或穿入主角。
- 3D 预览通过视觉验收后，才批量生成其余同类资产。每次替换一个资产族后，再做同角度回归截图。

## 苍山开场本轮空间建议

当前基准场景是 44×35.2 米。截图中主要问题除了网格资产风格朴素，还包括地面细密的颜色棋盘和地图间距对角色显得偏紧。现在建议把地图的**水平布局坐标放大 1.6 倍**，成为约 70.4×56.32 米；人物高度和建筑高度仍保持人体尺度，地标相对像素坐标不变。出生点到药摊约从 4.26 米变成 6.82 米；药摊到客栈约从 8.64 米变成 13.83 米。

这是有意把游戏世界拉开，而不是宣称原图每 100 像素对应 1.57 米的真实测量。原图比例仍决定空间关系；1.6 是可玩的关卡尺度。房门前、出生点、药摊和练武围场设为疏朗区；树石主要留在原图林缘和水岸；减少规则边缘石块和地面小色块。若验收后觉得路线过长，再整体回调布局系数，不单独移动每个房子。

### 2026-09-30 视觉校准记录

- 对照 `world-west.png`、`world-east.png` 与浏览器出生点截图后，发现核心差异来自区域布局：手工路线太宽，路线交点变成大块空地；单一草色地板缺少原图的暖泥色斑驳；随机散布的小树没有形成原图里贴着路径弯曲的岩石/植被边缘。增加 Hunyuan 建筑模型数量不会修复这些比例问题。
- 当前先将主路/支路宽度收回到地图像素比例乘以布局扩展系数后的约 1.85–2.45 米，按道路中心线的避让带从 225 像素收至 125 像素，并缩小建筑周围的清空矩形；地面和道路表面用实际 3D 网格顶点色加入确定性的多尺度色彩变化。
- 源图构图接近固定的 2.5D 画面，游戏场景改用正交相机并保留轨道旋转、缩放，让建筑仍有立体侧面，同时避免近景摊位和树比远景大出太多。
- 这只是第一轮基底校正。正式复刻要把原图拆成道路边界、岩石/林缘、田地、建筑占地和开阔区几类像素掩码；从掩码生成地形分区、路径网格和资产簇，再以相同固定镜头做同位置对照。单体 3D 资产只负责造型，像素坐标图层负责布局，材质与镜头负责统一视觉语言。

- 苍山牌坊跨越两张 `2240 × 3584` 子图的接缝。裁参考前先按 X 方向拼成 `4480 × 3584` 地图，再以拼接图坐标裁取 `(1650, 2050, 1050, 1300)`；禁止直接从单侧子图裁切，否则会切掉牌坊的一部分。ImageGen 已制成正、左、背、右视图，逐张保存在 `assets/generated/scene-assets/cangshan-paifang/`。当前可运行模型是 Blender 编辑的独立 3D 网格（77 个对象部件，约 1,840 面，尺寸约 `5.44 × 1.49 × 3.44 m`），锚点 `(2040, 2700)`，柱基各有独立碰撞范围。它修正了临时门架歪斜的问题，但必须标记为 Blender 资产，不能记作 Hunyuan 生成。世界构建器发现该 GLB 后会跳过旧门架；Three.js 在同一地图锚点加载单体 GLB。
- 百草药铺也完成了这条独立物件链：地图裁片 `(2800, 1950, 700, 700)` → ImageGen 同一药铺四视图 → 4 张分视图 → Blender 可编辑药铺 → GLB → Three.js 锚点 `(3110, 2300)`。模型当前是 Blender 几何，不是 Hunyuan 结果；构建器有独立 GLB 时跳过旧药铺。药铺单体范围约 `4.4 × 3.398 × 3.74 m`，碰撞代理保持地图清单范围。
- 资产批次逐个推进：一旦独立 GLB 已替代某个程序化物件，构建器必须跳过该物件的旧几何，运行时则在同一地图锚点加载新资产；碰撞和交互仍由地图清单里的代理维持。其余可见物件按资产清单排队，先药铺、桥/亭与摊位，再做重复树种和石灯/箱桶变体；地面、道路、水系和围栏始终从 2D 布局确定性生成。
